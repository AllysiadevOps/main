# Cross-Layer Verifier Conformance Vectors

Harpocrates parses the same verifier material in four places: the Noir circuit
defines it, the Python backend forwards it, the browser produces it, and the
Soroban registry acts on it. If any two of those disagree about what a valid
public-input frame is, the disagreement is a soundness bug — one layer accepts
what another rejects, and an attacker picks the gap.

This document defines the canonical codec, the shared corpus that pins it, and
how each layer is held to it.

## The codec: `hpx-vi/1` and `hpx-vi/2`

One canonical implementation per layer, all agreeing byte for byte:

| Layer | Implementation | Runner |
| --- | --- | --- |
| Backend | `backend/verifier_inputs.py` | `backend/test_conformance_vectors.py` |
| Browser | `frontend/src/verifierInputs.ts` | `frontend/src/verifierInputs.conformance.test.ts` |
| Contract | `contracts/contracts/harpocrates-registry/src/verifier_inputs.rs` | `contracts/contracts/harpocrates-registry/src/test_conformance.rs` |

Two corpora pin the codec, regenerated by `python zk/vectors/generate_vectors.py`:

- `zk/vectors/verifier_conformance_v1.json` — the original `hpx-vi/1` frames.
- `zk/vectors/verifier_conformance_v2.json` — `hpx-vi/2`, which appends a
  circuit version trailer so the wire format commits to the exact circuit that
  produced the proof.

### Frame layout

A `hpx-vi/1` silent-witness public-input frame is exactly **160 bytes**: five
32-byte big-endian BN254 field elements. Revocation-witness frames remain 128
bytes. `hpx-vi/2` adds the scoped, circuit-versioned frame described below.

`silent_witness/v1`

```
[  0.. 32)  video_hash_hi     16 zero bytes of padding, then the high 16 bytes
[ 32.. 64)  video_hash_lo     16 zero bytes of padding, then the low 16 bytes
[ 64.. 96)  credential_root
[ 96..128)  nullifier
[128..160)  domain_tag          SHA-256(protocol || version || network)
```

`revocation_witness/v1`

```
[  0.. 32)  revocation_root
[ 32.. 64)  nullifier
[ 64.. 96)  domain_separator   must equal REVOCATION_DOMAIN_SEPARATOR
[ 96..128)  credential_root
```

`silent_witness/v2` is the on-chain **scoped** frame (`verifier_scope` + `epoch`,
i.e. the 224-byte layout the registry has always parsed ad hoc) with the circuit
version committed as its trailing field:

```
[  0.. 32)  video_hash_hi     16 zero bytes of padding, then the high 16 bytes
[ 32.. 64)  video_hash_lo     16 zero bytes of padding, then the low 16 bytes
[ 64.. 96)  credential_root
[ 96..128)  nullifier
[128..160)  verifier_scope
[160..192)  epoch
[192..224)  domain_tag          SHA-256(protocol || version || network)
[224..256)  circuit_version     uint32 big-endian in the low 4 bytes; upper 28 zero
```

`verifier_scope` and `epoch` are full field elements: they are hash inputs, not
128-bit halves, so they carry no padding obligation — only the two video-hash
halves do. The registry still narrows `epoch` to a `u64` after the codec hands
back the raw field element; the codec itself never interprets it.

The domain separator is seven bytes of BN254 padding followed by the 25 ASCII
bytes of `HARPOCRATES_REVOCATION_V1`, i.e.
`00000000000000484152504f4352415445535f5245564f434154494f4e5f5631`. It is
byte-identical to `REVOCATION_DOMAIN_SEPARATOR` in the registry contract, and
the Rust runner asserts that directly rather than through a case.

### Domain-binding rejection vectors

`domain_tag` binds a proof to an exact `(protocol, circuit version, network)`
tuple, so it is not enough that *a* tag is present — it must be the tag for
*this* deployment. The corpus isolates each component so a regression in any one
is caught by name:

| Case | Rejected because |
| --- | --- |
| `sw-neg-045-domain-wrong-protocol` | tag recomputed with a different protocol component |
| `sw-neg-046-domain-wrong-circuit-version` | tag recomputed with a different circuit version (cross-version replay) |
| `sw-neg-047-domain-wrong-network` | tag recomputed with a different network component (cross-network replay) |

`generate_vectors.py` recomputes each tag as
`SHA-256(protocol' || version' || network')` with exactly one component changed,
so the value stays canonical and non-zero: the failure is a genuine
`domain_mismatch`, not a framing or canonicity error. The revocation separator
gets the equivalent treatment (`rv-neg-041-domain-off-by-one`, the V1 → V2
version byte).

### Canonical check order

The order is part of the contract — two layers that reject the same input for
different reasons are still a divergence, because operators and clients branch
on the code:

1. `length` — frame is not exactly the schema-specific length (160 bytes for
   `silent_witness/v1`, 128 bytes for `revocation_witness/v1`)
2. `padding` — a 128-bit half has a non-zero high 16 bytes (`silent_witness` only)
3. `non_canonical_field` — a field element is ≥ the BN254 scalar modulus, checked in index order
4. `zero_field` — a required identity field is zero, checked in index order
5. `domain_mismatch` — domain separator mismatch (`revocation_witness` only)
6. `proof_undersize` — proof blob below `MIN_PROOF_BYTES` (64)
7. `proof_oversize` — proof blob above `MAX_PROOF_BYTES` (65 536)

Public inputs are always classified before the proof blob.

The `hpx-vi/2` order inserts the circuit-version check immediately after
padding and restricts the later checks accordingly:

1. `length` — frame is not exactly 256 bytes for `silent_witness/v2`
2. `padding` — a video-hash half has a non-zero high 16 bytes
3. `version_mismatch` — the trailing `circuit_version` field's upper 28 bytes
   are non-zero, or the decoded u32 differs from `expected_circuit_version` (2).
   This is deliberately stricter than the selective-disclosure envelope's
   version *label*, whose parser reads the low 4 bytes and ignores the rest:
   here the trailer is the binding itself, so a non-canonical encoding of an
   otherwise-correct version must not pass (`sw2-neg-024-dirty-upper`)
4. `non_canonical_field` — checked on fields `[0..6]` (the two video-hash
   halves, credential root, nullifier, `verifier_scope`, `epoch`); the domain
   tag and the version trailer are compared byte for byte, never canonicalized
5. `zero_field` — checked on `credential_root`, `nullifier`, `domain_tag`; a
   zero `video_hash`, `verifier_scope` or `epoch` is structurally legal
6. `domain_mismatch` — domain tag differs from `silent_witness_domain_tag_hex`
7. `proof_undersize` / `proof_oversize` — proof blob outside 64..=65536

The version check runs before canonicity and zero-identity so that a frame
produced by a different circuit is always reported as a version problem, never
as a malformed identity — the reason matters to whoever has to fix it.

`unknown_schema` remains layer-local (schema dispatch is not a wire input) and
is exercised outside both corpora.

`malformed_hex` is also layer-local — hex decoding only happens where material
arrives as a string (backend and browser) — but it is pinned by a companion
corpus: `zk/vectors/malformed_public_inputs_v1.json`, regenerated by
`python zk/vectors/generate_malformed_public_inputs.py`. The Soroban registry
receives bytes, so the contract runner asserts the corpus at the strict hex
boundary and additionally feeds each case's raw presentation bytes to
`classify_public_inputs` for every schema, proving no byte-level interpretation
of a malformed presentation is ever accepted on chain.

## Vector format

```json
{
  "format": "harpocrates.verifier-conformance",
  "version": 1,
  "codec": "hpx-vi/1",
  "constants": { "public_inputs_len": 160, "min_proof_bytes": 64, "...": "..." },
  "schemas": { "silent_witness/v1": ["video_hash_hi", "..."] },
  "reject_codes": ["length", "padding", "..."],
  "cases": [
    {
      "id": "sw-neg-020-credential-root-equals-modulus",
      "schema": "silent_witness/v1",
      "description": "A field element equal to the modulus is a non-canonical encoding.",
      "public_inputs_hex": "...",
      "proof_hex": "...",
      "expect": { "accept": false, "reject_code": "non_canonical_field" }
    }
  ]
}
```

The `hpx-vi/2` corpus carries `"version": 2`, `"codec": "hpx-vi/2"`, the extra
constants `silent_witness_v2_field_count` (8),
`silent_witness_v2_public_inputs_len` (256) and `expected_circuit_version` (2),
schema `silent_witness/v2` (the scoped frame plus `circuit_version`), and
`version_mismatch` in `reject_codes`. Its case ids use the `sw2-pos-` /
`sw2-neg-` prefixes.

Case ids are stable and structured: `<schema>-<pos|neg>-<nnn>-<slug>`. The
structural corpus covers positive frames plus negative framing, padding, field
canonicity, zero identity fields, domain binding, cross-schema length traps,
circuit-version mismatch, and proof size bounds.

### Malformed public-input hex corpus

```json
{
  "format": "harpocrates.malformed-public-inputs",
  "version": 1,
  "codec": "hpx-vi/1",
  "reject_codes": ["malformed_hex"],
  "cases": [
    {
      "id": "mh-neg-030-0x-prefix",
      "field": "public_inputs",
      "description": "A 0x prefix is a presentation form, not part of the wire alphabet.",
      "value": "0x00",
      "expect": { "reject_code": "malformed_hex" }
    }
  ]
}
```

Case ids are `mh-neg-<nnn>-<slug>`. The corpus covers odd-length strings,
non-hex alphabet, whitespace/control characters, `0x`/`#` decorations, empty-ish
tokens, and non-ASCII lookalikes. Backend and browser runners assert every case
rejects with `malformed_hex` and that the rejection signal never echoes the
input presentation. The contract runner (`test_conformance.rs`) asserts every
case against the strict hex boundary with its expected category, and drives the
raw presentation bytes of every case through `classify_public_inputs` (all
three schemas) to pin that the on-chain classifier never accepts one.

## Artifact binding

Each runner asserts more than the cases:

- Constants in the corpus (`public_inputs_len`, `min_proof_bytes`,
  `max_proof_bytes`, the modulus, the domain separator) must equal the
  implementation constants. A corpus that drifts from the code fails before any
  case runs.
- `codec` and `version` must match what the runner expects.
- CI regenerates the structural corpus from `generate_vectors.py` and the
  malformed-hex corpus from `generate_malformed_public_inputs.py`, then `diff`s
  each against the committed file, so a hand-edited corpus — which would
  silently weaken every layer's assertions — fails.

## The real boundary

The contract runner drives **both** contract-side boundaries:

1. the pure `verifier_inputs` codec, and
2. the real on-chain entry point `classify_public_inputs(schema_id,
   public_inputs, proof_len)`, invoked through the generated contract client.

`classify_public_inputs` is read-only, side-effect free, and O(1) in the frame
size. It returns `0` for accepted material or the stable numeric reject code. It
takes a proof *length* rather than a proof blob, so classification never
transports proof material on chain.

`test_conformance.rs` also asserts the entry point is idempotent and consumes no
nullifier, and that an unknown `schema_id` returns a code rather than panicking.

## Compatibility and migration

`classify_public_inputs` gained `silent_witness/v2` **additively**; the
`hpx-vi/1` handling is byte-for-byte unchanged, and an unknown schema id still
returns a code rather than panicking.

On the registration path (`register_anonymous_verified`) the versioned envelope
is **required**:

- A 256-byte envelope appends the 32-byte `circuit_version` field that the
  circuit itself asserted in-circuit. It must decode to
  `EXPECTED_CIRCUIT_VERSION` (2); anything else — a stale version, zero, a
  non-canonical trailer — is rejected with
  `RegistryError::CircuitVersionMismatch` (#87).
- A bare 224-byte scoped frame commits no version at all, so its circuit version
  could only ever be *inferred* from the length. It is rejected with
  `RegistryError::CircuitVersionMismatch` (#87) before the verifier is reached,
  so no scoped proof can skip the commitment by omitting the trailer.

`sw2-neg-003-truncated-one-field` pins the two layers agreeing on that frame
without agreeing on the wording: the *strict* codec
(`classify_public_inputs`, schema `silent_witness/v2`) rejects it with `length`,
because a frame that names no circuit cannot be classified as one, and the
registry rejects it with the dedicated error 87 rather than the generic
`InvalidPublicInputs`. Stored evidence is untouched either way, because
`circuit_version` is never written to `ProofRecord`.

Migration for provers:

1. Confirm every in-flight prover emits canonical frames (use
   `classify_public_inputs` as a pre-flight — that is what it is for).
2. Ship the v2 codec id (`hpx-vi/2`) and the envelope trailer behind the new
   constants.
3. Re-point the public-input encoding at the versioned frame; the committed
   version, not the byte length, is what the verifier trusts from now on.
4. Update both corpora `version` fields and this document in the same commit.

**Rollback:** deploying a pre-#368 wasm removes the `silent_witness/v2` schema
from `classify_public_inputs` and rejects the 256-byte envelope (224-byte-only,
as before), so rolling back means provers go back to the bare frame — exactly the
acceptance this change closes. Records written through the envelope are ordinary
`ProofRecord`s with no version marker, so nothing persisted is misread by the
older contract.

**External verifiers:** the proof-verifier contract receives the whole public
-input blob, so any verifier that whitelists frame lengths must learn 256
alongside 128 / 160. The registry's own test doubles still list 224 as well: they
stand in for the barretenberg verifier and model the lengths *it* can parse, not
the registry's frame policy, and a bare frame now reaches them only if a test
calls the double directly.

## Running the runners

```bash
# Python
cd backend && python -m pytest test_conformance_vectors.py -q

# Browser
cd frontend && npx vitest run src/verifierInputs.conformance.test.ts

# Contract
cd contracts && cargo test --workspace conformance
```

CI runs all three: the Python runner in `zk-ci.yml`, the Rust runner in
`contracts-ci.yml`, the TypeScript runner in `frontend-ci.yml`. Both contract
and frontend workflows trigger on `zk/vectors/**`, so a corpus change re-runs
every layer.

## Mismatch diagnostics

A divergence fails exactly one of the three suites and names the offending case
id, so diagnosis does not require re-deriving which layer is wrong:

```
sw-neg-020-credential-root-equals-modulus: expected 'non_canonical_field', got None
```

The Rust runner collects **all** mismatches before asserting, so a systematic
divergence shows as a list rather than one case at a time.

## Constant-time comparisons

Every layer compares protocol bindings (`domain_tag`, the revocation
`domain_separator`, zero sentinels, half-padding) with a helper that folds all
bytes into one accumulator instead of exiting on the first difference:

| Layer | Helper |
| --- | --- |
| Python (`backend/verifier_inputs.py`) | `constant_time_equals` (`hmac.compare_digest`) |
| Browser (`frontend/src/verifierInputs.ts`) | `constantTimeEquals` |
| Soroban codec (`verifier_inputs.rs`) | `constant_time_eq` |

The `silent_witness/v2` envelope compares its `domain_tag` through the same
helper, so the scoped frame gets identical treatment to v1 (#368). Its
`circuit_version` is the exception and does not need the helper: the accepted
value is a small public constant decoded from a field element, so the check is a
single arithmetic comparison with no byte-prefix early exit to leak.

The backend metrics token check (`/metrics`) uses `hmac.compare_digest` on both
candidate headers, matching the existing register API key check.

**Threat model.** Public-input bytes are not secret, so this is defense in
depth: a caller probing the verifier boundary cannot learn how many leading
bytes of an expected binding matched from rejection latency. The metrics token
*is* a secret, where this closes a real timing oracle. Length is public and a
length mismatch returns early.

**Circuits are unchanged.** `Field ==` in Noir lowers to fixed arithmetic
constraints and the set-membership predicate scans every slot, so circuit
behaviour is already data-independent. No ACIR, verification key, or entry in
`zk/browser.artifacts.manifest.json` changes.

**Compatibility and rollback.** Accept/reject decisions and reject codes are
identical, so the corpus needs no version bump and stored evidence is
unaffected. Rolling back is a plain revert with no migration.

## Privacy

Rejections carry a stable machine code and at most a field *name* — never
witness material, proof bytes, or public-input bytes. `version_mismatch` is no
exception: the codec reports the field name `circuit_version` only, never the
declared value, and the two on-chain surfaces expose nothing more —
`classify_public_inputs` returns the numeric code, while registration panics
with the dedicated `RegistryError::CircuitVersionMismatch`, which discloses only
that the envelope's own version claim did not match this build. `VerifierInputError.signal()`
(Python) and `VerifierInputError.signal()` (TypeScript) return exactly
`{codec, reject_code, field?}`, and both runners assert that a rejection of a
tampered frame does not echo any part of that frame. The contract collapses all
codec rejections onto the pre-existing `InvalidPublicInputs` / `InvalidProof`
errors, so the on-chain error surface discloses nothing new.

## Limitations

- The corpus pins *structural* agreement. It does not pin cryptographic
  agreement: whether all four layers accept the same **proofs** requires real
  proving artifacts, which is the reproducible-build pipeline's job
  (`docs/zk-reproducible-builds.md`).
- The v2 corpus pins the version *signal* (a frame must carry
  `circuit_version == 2`), not the domain-tag constant itself — which the v1
  corpus and the contract's `expected_domain_tag` already pin. Regenerating the
  circuit with a new version forces `EXPECTED_CIRCUIT_VERSION`,
  `CURRENT_CIRCUIT_VERSION`, and this corpus to move in lockstep.
- The Noir circuit itself is not a runner. It defines the layout the corpus
  encodes, but `nargo test` does not consume the JSON. Circuit-side drift is
  caught indirectly, when regenerated artifacts change the frame the other three
  layers see.
- The Rust runner reads the corpus with a small line-oriented scanner rather
  than a JSON crate, to keep third-party code out of a contract crate. It
  depends on the generator's stable key ordering; a structurally reordered
  corpus parses as zero cases, which `corpus_is_non_empty_and_versioned`
  rejects.
